# 移动端防窥场景审计（2026-10-14）

> 本文保留 1.3.10 历史验收情况。1.3.11 已调整过度遮挡、后台恢复、启动 / 设备锁定和截图默认策略，当前行为见 [1.3.11 防窥策略](mobile-privacy-policy-2026-10-14.md)。

适用版本：1.3.10。范围是移动端显示、操作与生命周期的防窥保护，不等同于本地数据库加密、服务器访问控制或安全渗透测试。本次通过源代码检查、行为测试、原生插件预构建检查验证；没有连接 iPhone，不能把自动化验证写成真机验收。

## 标签交互

- 首页仅显示记录数大于零的标签，左右滑动使用同一集合。当前标签被删除或记录数归零后返回“全部”；初次加载和读取失败不误清除选择。
- 管理页仍显示全部标签，空标签可以重命名、改色和删除。点击名称直接打开编辑弹窗，移除更多按钮；右侧长按手柄拖动排序。
- 删除选项和删除关联记录的二次确认均在受保护的编辑弹窗内。排序失败回退，服务端错误在页面内展示。

## 场景与验证

| 场景 | 措施与本轮结论 | 验证依据 |
| --- | --- | --- |
| 首页正文、标签、搜索历史、评论及批量选择 | 锁定时卸载历史界面；仅允许设置中授权的全新快速记录 | HomeScreen、InlineComments、CommentInputModal 测试 |
| 日历、日期记录、我的页面 | 锁定或前台隐私检查尚未完成时隐藏内容、标题与底部导航，阻止切换 | MainTabs、Calendar 集成与单测；新增未 ready 场景 |
| 详情、草稿、同步记录、个人资料、标签及所有设置子页 | 新增统一 PrivacyBoundary；解锁控制器提升至认证导航上方，直接进入子页也必须先通过检查 | PrivacyBoundary 集成覆盖冷启动、锁定卸载、恢复等待 |
| 编辑旧记录及未发送内容 | 保留编辑状态但隐藏界面，停止媒体、录音及键盘；原提交正文改为页面展开，避免系统弹窗残留 | Compose 单测/集成、PrivacyBoundary 保留编辑状态测试 |
| 标签编辑、图片查看、评论等原生 Modal | 历史容器锁定后卸载其子树；标签编辑自行清除编辑状态 | TagDragging 使用真实 Modal 的锁定测试；PrivacyBoundary 媒体/Modal 卸载测试 |
| 音频、视频、独立音频页 | 隐藏时卸载播放器并明确 pause；禁用视频画中画，避免脱离受保护页面 | Audio/Video 组件测试及页面边界测试；原生播放体验待设备复验 |
| 自动锁定、切后台、返回前台 | 进入 inactive/background 立即置为未 ready；读取完成前不展示旧内容；不把进入后台当成用户活动延长超时 | usePrivacyMode：超时、延迟存储读取、后台恢复、失败关闭测试 |
| Face ID、密码验证、切账号 | 同一控制器管理验证；账号或认证版本变化后丢弃迟到结果；密码验证不再提前写入已解锁状态 | usePrivacyMode、auth、historyPrivacy 测试 |
| 多任务缩略图、通知中心、后台时仍打开 Modal | iOS 原生 UIWindow 不透明遮罩，在失焦时立即覆盖，取消原来的渐入；JS 遮罩作为后备，启动时已在后台也覆盖 | AppBackgroundBlur 测试；Expo iOS dangerous mod 执行及幂等检查；真机待验 |
| 截图、录屏、投屏 | iOS 与 Android 均调用 Expo screen-capture 防护；Android 使用系统 FLAG_SECURE；iOS 依赖 SDK 的 secure text layer 与录屏保护 | ScreenCaptureProtection 调用测试；不同系统版本、Modal、投屏必须真机复验，不能承诺任意设备均不可截取 |
| 分享、复制、地图跳转 | 敏感操作捕获账号与隐私状态版本；下载、系统能力查询、确认回调后重新校验；跨锁再解锁也不能继续旧操作；系统地图确认不再显示坐标 | privacyOperation、shareService、useBBTalkActions、HomeScreen 测试 |
| 导出、导入及缓存清除 | 异步步骤和确认回调校验；锁定后不继续分享导出；失效导出文件尽力清理；导入错误详情留在页面，系统通知不显示附件名/行内容 | DataManagement 测试含下载/选择文件期间锁定再解锁 |
| 存储配置与连接测试 | 配置、桶名、端点和测试结果均受页面边界保护；详细错误改为内联，锁定/卸载后拒绝迟到反馈及旧删除确认 | StorageSettings、CacheManagement 单测及 SettingsFlows 集成 |
| 批量删除、标签及可见性修改 | 确认跨锁失效，每次下一条请求前重新检查；已发出的请求可以结束，后续停止，锁后不弹原始错误 | useBatchMode 单测含跨锁确认、处理中锁定 |
| 桌面小组件数据 | JS 数据层锁定/未 ready/未登录强制空记录；清理使旧同步失效，写入串行，避免迟到任务恢复正文 | Widget 服务测试；仓库没有 HomeWidget 原生模块/WidgetKit 扩展，当前不能声称已完成桌面小组件真机保护 |
| 离线记录与同步 | 页面读取仍通过隐私边界；已授权保存的同步可以在锁定后完成，锁定不删除草稿和业务数据 | Drafts、Outbox、会话缓存回归；此处是显示保护，不是磁盘加密 |

## 明确边界

1. 已交给系统分享面板、外部地图/浏览器、照片选择器、剪贴板或接收方应用的内容，不能由本 App 统一遮盖或撤回。校验防止的是锁定后的新交付。导出成功后保存的备份属于用户主动导出，文件本身不受 App 解锁界面保护。
2. Web 没有等价的系统截图禁止能力；可执行页面锁定与异步校验，无法控制操作系统截图。外部相机、已解锁时旁观者看到屏幕也不在软件截图防护范围。
3. 本次没有发现移动端启用推送通知正文、系统搜索索引、Live Activity 或原生桌面 widget 的实现；不能将不存在的功能记作“已防护”。后续加入这些出口时必须默认隐藏私密摘要并补验。
4. 普通系统确认可能保留操作名称、是否置顶/公开及记录数量等元信息；正文、标签名称、坐标和存储连接详情不应放入这些不可随 React 页面卸载的弹窗。若产品要求连操作元信息也隐藏，需要进一步替换全部系统确认。
5. 本地缓存、草稿和备份的静态加密、设备越狱/调试、服务器日志及附件鉴权不属于本次显示防窥验收。

## 原生实现与设备复验

`mobile/plugins/withPrivacyCurtain.js` 只修改 expo-screen-capture 8.0.10 的后台遮罩，保留截图保护实现。版本及修改前/后的 Swift 源码 SHA-256 均被校验；依赖升级不匹配时主动阻止构建，必须重新审查。插件测试验证未知源码拒绝、幂等与输出结构。Windows 环境不支持完成 iOS 原生编译，最终编译需 EAS macOS 构建。

参考：[Expo SDK 54 ScreenCapture](https://docs.expo.dev/versions/v54.0.0/sdk/screen-capture/)。原生截图与录屏效果以实际 iOS/Android 系统验证为准。

TestFlight 逐项复验：

- 首页、日历、详情、标签编辑弹窗、图片全屏、音视频播放、存储配置页分别切后台，检查多任务卡片与返回前台是否闪现。
- 设置短超时，在各页面等待锁定；解锁、取消 Face ID、Face ID 失败后密码解锁；切账号后旧验证结果不应放行。
- 截图、开始/停止录屏、投屏时测试普通页面和 Modal；下拉通知中心、来电、锁屏再返回。
- 分享下载、导出下载和文件选择期间锁定，返回后不继续交付旧内容；已交付外部应用的内容按上面的边界判断。
- 空标签隐藏、当前标签清空、编辑弹窗键盘与长列表拖动；检查大字体、深色模式及真实触摸体验。

自动化与发布的最终结果见 [移动端验收记录](../mobile/RELEASE_READINESS.md)。
