# 个人文案欢迎页

正式 Web 的「设置 → 文案欢迎页」（`/settings/welcome`）可管理自己的文案池。添加文案后开启开关，下次打开或刷新记录首页就会展示独立扉页；点击「进入记录」继续使用。

扉页采用「日落明信片」视觉：桃粉天空、杏色太阳、蓝紫远山与半透明文案卡，适配手机屏幕和深色模式。

- 文案池、可选出处、开关和轮换进度按账号保存；其他账号不能通过 API 读取或修改。
- 随机轮换，一轮看完再重新排列；至少两条时避免相邻重复。只有一条时会重复，空池或关闭时直接进入记录。
- 设置页支持添加、编辑、删除及预览，预览不消耗轮换进度。自己的记录菜单中可选「加入文案池」，调整文本并保存后才入池。
- 上限 200 条，每条正文最多 1000 字符，出处最多 200 字符；文案按纯文本显示并保留换行，不执行 HTML。
- 第一次使用默认关闭、池子为空，不预置或自动上传示例文案。
- 内部导航、短暂切换浏览器标签页不重复弹出；新打开标签页或刷新首页算一次打开。直接访问设置、详情、公开页和桌面授权链接不会被拦截。
- 防窥锁定优先，欢迎页也遵循自动锁定时长。获取文案失败或超过 5 秒会进入记录，也可以主动跳过等待。
- 多端编辑冲突会提示重新载入，未保存的输入保留；不会静默覆盖其他页面的修改。

本版实现 Web 和共享后端接口。iOS/Android 原生端尚未接入；选择策略为随机轮换，未调用 AI 服务。文案继承现有账号鉴权，并非端到端加密数据。

## 部署与备份

在现有数据库完成备份后，从 `backend/` 执行：

```powershell
uv run python -m cli migrate
```

然后构建并部署正式 `frontend/` Web。新增 `0005_welcome_settings` 迁移仅创建个人文案表，不改历史记录，无需新增环境变量。回退应用时保留新增表，不自动删除用户文案。

JSON/ZIP 账号导出和完整备份包含可选 `welcome` 配置。旧备份继续兼容；导入仅恢复到尚无文案配置的账号，目标已有配置时保留目标文案池，避免覆盖。轮换历史不导出。

## 接口

路径为 `/api/v1/bbtalk/settings/welcome`，仅当前已认证用户可访问，响应禁止缓存。

- `GET`：返回 `{enabled, quotes, revision}`，不改变进度。
- `PATCH`：保存同结构完整配置；`quotes` 为 `{id, text, source}` 数组。`revision` 不匹配返回 409；不接受 `user_id` 或其他未知字段。
- `POST /next`：返回 `{quote}`，关闭或空池时 `quote` 为 null。此请求消耗一次轮换，请勿作为预加载或健康探针。

写请求按账号串行化，首次鉴权后释放只读快照，取得写锁并再次验证凭据，避免 SQLite 读事务升级失败。配置修改递增 revision，单纯取句不递增。数据库权限和密钥保护仍沿用现有部署规范。
