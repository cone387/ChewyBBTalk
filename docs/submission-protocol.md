# 发布去重与编辑版本协议

后端支持兼容扩展；旧客户端不带新增请求头时保留原行为。三端接入状态以 `multi-client-readiness/tasks.md` 为准，后端支持不等于客户端已获得完整保护。

## 发布与结果核对

创建记录 `POST /api/v1/bbtalk/` 可带 `Idempotency-Key`，值为 8–128 位字母、数字、下划线或短横线。客户端应在请求前按服务器、账号持久保存随机键与原始 JSON 载荷。

- 首次成功返回 201。
- 同账号、同键、同载荷重试返回 200、同一记录 UID，以及 `Idempotency-Replayed: true`。响应为当前记录状态，不是历史快照。
- 同键但载荷不同返回 409 / `submission_conflict`，不覆盖记录。
- 原记录已删除返回 410 / `submission_deleted`，不会重新创建。
- 数据库暂时冲突返回 503 / `submission_retry` 和 `Retry-After: 1`；核对或重试必须保留同一键。

`GET /api/v1/bbtalk/submission-status/?key=<key>` 按认证用户查询：成功返回当前记录，删除返回 410，没有已提交回执返回 404。404 不能证明一个并发请求已经停止，因此后续仍应沿用原键重试。接口响应禁止缓存。

回执与记录/标签同事务提交，以数据库用户+键唯一约束保证去重。回执保留到用户删除，不因记录删除或时间经过自动清除。回执仅存摘要、键和记录引用，不复制正文/附件。账号数据 ZIP 不包含传输回执；数据库整体恢复/迁移与账号内容导入是不同操作，客户端不能把旧服务器未确认提交直接当作新服务器待发布任务。

## 条件编辑

`PATCH/PUT /api/v1/bbtalk/<uid>/` 可携带 `If-Match: "<update_time>"`，值取读取记录返回的完整带时区更新时间，不做客户端截断。服务器在事务内锁定并比较版本后保存。

旧版本返回 409 / `edit_conflict`，`current` 包含该用户有权查看的最新记录。客户端保留输入，展示最新内容供核对；在用户决定后使用最新版本重新提交。请求丢失后应先读取最新内容核对，不自动放弃条件覆盖。格式错误返回 400，其他账号不可访问。

SQLite 并发写冲突可能返回 503；支持行锁的数据库按记录串行比较。跨域允许新增请求头；此协议不依赖浏览器离线 worker。

## Web 接入

Web 新建记录在请求前将提交键和原始载荷保存至 IndexedDB，与草稿版本在同一事务中核对，避免过期标签页绕过已清除草稿重新发布。保存失败时保留输入并阻止发布。

结果不确定时，编辑器展示原提交，支持只读核对或沿用原键重试；修改后的输入不会替代原提交载荷。恢复确认不清除当前输入。正常发布在确认结果、清除草稿后才移除已确认提交；任一步本地保存失败均保留恢复依据。不会自动离线发布。

编辑携带打开或恢复草稿时的版本；409 冲突显示服务器最新正文、标签、可见性和附件，保留本地输入。用户核对并选择继续编辑后，下一次保存基于该新版本，期间再次变化仍会被拒绝。

浏览器测试 submissions.spec.ts 使用真实 Django API，模拟服务器提交成功后响应丢失，检查刷新重试的键、记录 UID 和记录数量；另覆盖未知结果、修改载荷拦截和编辑冲突核对。移动端与桌面端已补界面集成回归，边界见下文。

## 桌面接入与旧草稿

桌面发布由主进程保存原始请求并发出，渲染进程只通过带会话身份的 IPC 操作。返回窗口和网络恢复时尝试核对待确认结果，不自动 POST。服务端已删除的记录显示已删除状态，原键重试不重建。

新草稿保存在 electron-store 的 compose.drafts 中，按服务器 URL 和 JWT 用户 ID 隔离。旧 compose.draft 没有可靠的身份归属，仍保留在原配置文件中，不自动载入任何账号；已有旧草稿的用户可从配置文件取回后粘贴到确认归属的账号。提交回执保存在 compose.submissions；结果不确定时不应手动删除这些条目。

## 前台刷新

Web 在窗口获得焦点、页面恢复可见或网络恢复时，以当前筛选刷新列表；同一秒内的重复事件合并。移动端在 Home 获得焦点、AppState 恢复 active 或离线转在线时刷新，保持已提交搜索词、标签及日期条件。下拉刷新和分页沿用同一组搜索条件，正在输入但尚未提交的搜索词不替换已应用条件。

两端列表仅接受当前请求的结果，旧筛选或旧分页请求的成功/失败不能覆盖新结果。会话内保留乐观删除的隐藏标识，避免撤销等待期间刷新重新显示记录；撤销或删除失败恢复时移除标识。编辑器输入独立保留。


## 原生与桌面验收边界

原生 ComposeScreen 在 AsyncStorage 中按会话保存原键和完整载荷；持久写入失败不发送发布。
恢复操作先将当前编辑内容另存草稿，再核对或重试原提交；草稿包含正文、可见性、附件和位置，兼容旧纯正文格式。
编辑冲突保留输入并要求用户核对新版本后再保存。真实组件集成命令和替换边界见 [原生测试说明](../mobile/integration/README.md)。

桌面恢复操作在核对前同步保存当前正文草稿，恢复面板与长文本参与窗口高度计算，达到上限后滚动。
测试使用真实 Electron 进程、磁盘配置、IPC、窗口和 Django，验证响应丢失后的完整进程重启、重试和账号切换；
说明见 [桌面集成测试](../frontend/desktop-integration/README.md)。桌面日常草稿仍为正文，原提交回执保存完整附件载荷；不承诺未发布的新附件草稿持久化。
这些自动回归不代替真机、系统安装包、托盘或系统权限验收。
