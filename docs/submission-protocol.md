# 发布去重与编辑版本协议

后端支持兼容扩展；旧客户端不带新增请求头时保留原行为。三端接入状态以 `multi-client-readiness/tasks.md` 为准，后端支持不等于客户端已获得完整保护。

## 发布与结果核对

创建记录 `POST /api/v1/bbtalk/` 可带 `Idempotency-Key`，值为 8–128 位字母、数字、下划线或短横线。客户端应在请求前按服务器、账号持久保存随机键与原始 JSON 载荷。

- 首次成功返回 201。
- 同账号、同键、同载荷重试返回 200、同一记录 UID，以及 `Idempotency-Replayed: true`。响应为当前记录状态，不是历史快照。
- 同键但载荷不同返回 409 / `submission_conflict`，不覆盖记录。
- 原记录已删除返回 410 / `submission_deleted`，不会重新创建。
- 数据库暂时冲突返回 503 / `submission_retry` 和 `Retry-After: 1`；核对或重试必须保留同一键。

`GET /api/v1/bbtalk/submission-status/?key=<key>` 按认证用户查询：成功返回当前记录，删除返回 410，没有已提交回执返回 404。404 不能证明一个并发请求已经停止，因此后续仍应沿用原键重试。接口响应禁止缓存。

回执与记录/标签同事务提交，以数据库用户+键唯一约束保证去重。回执保留到用户删除，不因记录删除或时间经过自动清除。回执仅存摘要、键和记录引用，不复制正文/附件。账号数据 ZIP 不包含传输回执；数据库整体恢复/迁移与账号内容导入是不同操作，客户端不能把旧服务器未确认提交直接当作新服务器待发布任务。

## 条件编辑

`PATCH/PUT /api/v1/bbtalk/<uid>/` 可携带 `If-Match: "<update_time>"`，值取读取记录返回的完整带时区更新时间，不做客户端截断。服务器在事务内锁定并比较版本后保存。

旧版本返回 409 / `edit_conflict`，`current` 包含该用户有权查看的最新记录。客户端保留输入，展示最新内容供核对；在用户决定后使用最新版本重新提交。请求丢失后应先读取最新内容核对，不自动放弃条件覆盖。格式错误返回 400，其他账号不可访问。

SQLite 并发写冲突可能返回 503；支持行锁的数据库按记录串行比较。跨域允许新增请求头；此协议不依赖浏览器离线 worker。
