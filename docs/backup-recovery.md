# 备份管理与恢复

Web 的“设置 → 数据管理 → 服务器备份”支持创建当前账号的完整 ZIP、查看最近任务状态、下载历史备份。创建时保留最近 7 份；旧版本留下的 ZIP 仍能下载，但不能据此假定附件完整。

## 存储与定时任务

默认目录为 `DATA_DIR/backups/<user-id>/`。可通过 `BACKUP_ROOT` 指定 API 与命令共用的根目录；命令的 `--output-dir` 仍可单次覆盖。备份不包含登录密码、S3 secret 或整个服务数据库，恢复 S3 配置后需重新填写密钥。

```sh
uv run python chewy_space/manage.py backup_data --dry-run
uv run python chewy_space/manage.py backup_data --user-id 1 --keep 7
```

页面和定时命令共用账号级进程锁及状态文件。程序异常退出后锁由系统释放；状态仍显示运行中而锁已释放时，页面显示“已中断”。不要手动删除正在使用的锁文件。

创建请求同步执行。网络中断或代理超时不表示服务器停止备份，可刷新列表核对真实状态；同账号重复创建会返回 409。体积较大的备份可由已有宿主机定时命令执行。

## 完整性与失败处理

包含附件的 ZIP 增加 `manifest.json`，记录数据文件和附件的大小及 SHA-256。读取附件失败时整份导出失败；新 ZIP 原子写入成功后才清理旧备份。摘要用于发现缺件和内容损坏，不是数字签名。

导入新 ZIP 前会检查清单，缺件或损坏在数据库及存储写入前拒绝。旧 ZIP、纯 JSON 继续支持：缺少附件或无法关联评论时会显示跳过数量，单项错误会列入结果报告；应检查报告后再决定是否重试。

原记录与新附件的 UID 在冲突时会重新映射；可恢复正文、标签、评论、可见性、置顶、上下文、时间和附件内容。恢复范围是导出账号自身的数据，不会授权读取其他账号的备份。

备份与服务同盘不能抵御宿主机磁盘损坏，建议下载后另存至其他设备。完整恢复应先在隔离账号或测试实例演练，确认内容和附件可读后再用于正式迁移。

## 自动验证

`test_backup_management.py` 使用临时目录和真实本地存储完成跨账号恢复，并核对字段、文件字节、权限、锁及失败清理；`test_backup_integrity.py` 验证摘要、缺件与篡改拒绝；`backups.spec.ts` 使用真实 Django/IndexedDB 环境验证页面创建、下载、导入及错误报告。
