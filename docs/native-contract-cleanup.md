## 当前契约

- API 3.0.0 仅接受规范无尾斜杠路径。移除格式后缀、存储 create/delete 别名和旧 PUT 部分更新行为；PUT 替换、PATCH 部分更新。
- 查询使用具名日期字段与重复的 tags 参数；未知字段返回 422。记录载荷仅接受 tags 数组，不再解释 post_tags。
- 分页统一为 items、total、page、page_size、has_more；记录额外提供未筛选的 total_count，评论额外提供 revision。越界页返回 200 空集合。标签仍返回完整数组。
- 评论始终分页；三端移除旧页结构及数组回退。已无生产调用者的全量评论辅助方法删除。
- JWT 使用 sub/purpose，Cookie 使用 cb_session/cb_csrf，CSRF 请求头使用 X-CSRF-Token。撤销入口为 /auth/token/revoke，模型为 RefreshToken/RevokedToken。
- Swagger、ReDoc、OpenAPI 分别为 /docs、/redoc、/openapi.json；两套 Nginx、探针和当前规范同步更新。
- 桌面持久数据在独立版本迁移中转换旧标签。待确认提交先查回执；对象属性顺序不影响载荷相等判断，已确认的相同载荷复用原结果，避免升级重试重复发布。
- 附件链接仅规范化明确的附件 API 路径，远端对象存储签名链接保持原主机及查询参数。

## 数据与升级

新增 Alembic 0004_native_credentials：把既有有效 PBKDF2/scrypt 凭据转换为带版本与算法参数的原生 JSON，保留盐和摘要字节，无需用户重设密码。凭据列扩展为 Text（MySQL LONGTEXT），blacklisted_at 改名为 revoked_at，并保留微秒精度。运行认证代码不再理解旧密码序列化格式。

不支持的密码成本和可疑历史格式在整条升级链的 DDL 之前拒绝，避免账号被静默锁定或未知凭据意外可用。0004 可识别 MySQL 已提交的扩列、重命名以及部分密码转换状态，校验结构后继续迁移；字段缺失或新旧字段同时存在时明确拒绝。此恢复能力不代替 0003 中断时的备份与人工核验。

部署必须同时更新服务端和客户端，停写并备份数据库、附件、数据目录和密钥，再运行 `uv run python -m cli migrate`。旧客户端协议及旧 JWT 不再接受，浏览器和原生端需要重新登录。此次未操作线上容器或数据库。

冻结的历史迁移、旧库测试夹具、升级工具中的旧实例识别、审计档案以及回滚备份保留。这些承担旧实例升级与追溯用途，不参与当前 HTTP 契约。cb_migration_archive 中的历史元数据未删除；业务权限字段与业务表名不因外观相似而无意义改名。
