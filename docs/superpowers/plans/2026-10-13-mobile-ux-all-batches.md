# Mobile UX All Batches Implementation Plan

**Goal:** 完成用户批准的三批移动体验迭代：快速记录、可靠保存、便捷找回。

**Architecture:** 保留现有导航、主题、草稿与服务器协议。提取账号隔离的草稿目录、日历缓存和持久化同步队列；队列复用提交幂等键与编辑版本检查。界面展示真实持久化状态。

**Tech Stack:** Expo 54 / React Native / TypeScript / AsyncStorage / Redux / Jest。

## Scope and constraints

- 本计划承接对话中用户“全部批次都迭代好”的执行授权，当前工作区实现，最终集中审查；不发布商店或部署。
- 根目录保持整洁，临时文件只在 `.tmp/mobile-ux/`；构建输出在 `mobile/dist/`。
- 账号、服务器隔离；退出登录后禁止旧请求继续产生新写入；锁定期间隐藏草稿、记录和队列内容。
- 草稿不自动发布。只有用户点击保存/发布才加入提交队列；公开内容必须已明确确认。
- 离线队列支持文字、附件、新建与编辑；持久化后可退出。连接恢复、启动、前台恢复自动重试可重试任务；明确错误与冲突等待用户处理。
- 不承诺操作系统强杀期间后台执行。重启后继续持久化队列。
- 真机验收与自动化/浏览器验收分别记录，无法实际验证的项目不得记为通过。

## Review focus

1. 服务器已写入但客户端超时/强杀：同一幂等键不能重复创建记录。
2. 队列上传中换账号：旧附件和迟到结果不能写入新账号，也不能被清理误删。
3. 编辑离线期间远端被修改：保留双方内容，明确选择后才能覆盖。
4. 查询/日期切换后旧响应迟到：页面不能回退到旧结果；日历缓存不能跨账号。
5. 草稿与队列并存、后台恢复、锁定：可见入口准确，隐私锁下不暴露摘要。
