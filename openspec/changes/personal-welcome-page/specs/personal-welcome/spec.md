## ADDED Requirements

### Requirement: 私有文案池
系统 SHALL 只允许用户读写自己的文案池与开关，默认关闭、空池，不接受任意账号标识；支持新增编辑删除及可选出处，最多 200 条，正文 1–1000 字符，出处至多 200 字符，拒绝空白、重复 ID 与重复正文。

#### Scenario: 用户隔离与校验
- **WHEN** 用户 A 保存文案，用户 B 读取自己的配置
- **THEN** B 不会得到 A 的文案，匿名访问拒绝，非法输入返回 422

#### Scenario: 并发修改
- **WHEN** 旧 revision 的客户端保存配置
- **THEN** 返回 409 且保留新配置，客户端保留未保存输入

### Requirement: 随机轮换
系统 SHALL 将个人文案随机轮换，用完再循环，多条时相邻不重复，进度按账号持久化。

#### Scenario: 多端轮换
- **WHEN** 同账号连续请求 N 条文案且池内有 N 条
- **THEN** 每条恰好出现一次，下一轮首条不同于上一轮末条

#### Scenario: 单条及关闭
- **WHEN** 池内仅一条，或为空，或开关关闭
- **THEN** 单条允许重复；空池或关闭返回 null

### Requirement: 欢迎页生命周期
正式 Web SHALL 在已登录且解锁后的首页启动展示欢迎页，支持进入记录、换一句和设置入口；新打开/刷新可再次展示，内部导航及短暂切后台不会重复展示。

#### Scenario: 门禁与故障
- **WHEN** 用户未登录、已锁定、访问深链接、取句失败或等待超过 5 秒
- **THEN** 不泄露私密文案，分别遵循原入口、锁定、目的地或进入记录，不阻塞主要功能

#### Scenario: 退出与账号切换
- **WHEN** 用户进入记录后切换页面，或切换登录账号
- **THEN** 同会话不重复弹出，旧账号文案立即清除且迟到响应不能显示

### Requirement: 管理与预览
Web SHALL 提供设置入口、保存反馈、纯文本预览和从自己记录加入文案的入口；预览不消耗轮换进度。

#### Scenario: 从记录提取
- **WHEN** 用户在自己的记录菜单选择加入文案池
- **THEN** 打开个人设置编辑器并预填正文，用户编辑保存后才进入池

### Requirement: 备份恢复
系统 SHALL 将文案配置包含在账号导出中，兼容旧备份；导入不覆盖目标已有配置。

#### Scenario: 跨账号恢复
- **WHEN** 用户向尚无文案配置的目标账号导入备份
- **THEN** 恢复文案与开关到目标账号，轮换进度重新开始，原账号不变
