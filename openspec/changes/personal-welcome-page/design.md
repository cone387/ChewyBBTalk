## Context

用户已确认个人文案池、独立欢迎页及可关闭，并要求做一版体验。正式 Web 位于 frontend/，当前认证与防窥门禁由 App 管理。已有用户工作修改位于产品素材说明，不纳入本次修改。

## Goals / Non-Goals

- 实现账号隔离的文案池、云端开关和跨浏览器轮换；Web 可编辑、预览并从自己的记录提取文案。
- 本版不接入 AI、不实现内容加密或原生客户端 UI，不改变公开页与桌面授权深链接。

## Decisions

### 方案选型

- 新增 cb_welcome_settings：user_id 主键/级联外键，enabled 默认 false，quotes JSON，revision 整数，remaining JSON，last_id。最多 200 条，每条正文 1–1000 字符、出处 0–200 字符，唯一稳定 ID。字段均通过严格 schema 验证，禁止客户端指定 user_id。
- GET/PATCH /api/v1/bbtalk/settings/welcome 读取/保存完整配置；PATCH 带 revision 防止多端覆盖，冲突返回 409。POST /next 返回 quote 或 null；读取不消耗队列。写操作先锁账号行（SQLite 用无变化 UPDATE），同一事务维护队列与设置。
- 写路由先结束初始鉴权只读快照，以账号锁 UPDATE 开始新事务，再在锁内重新鉴权；设置读取采用 FOR UPDATE。锁操作显式保留用户 update_time，不能将取句记为资料修改。备份导入服务不主动回滚调用方事务。
- 随机打乱剩余 ID，耗尽后重建；新轮第一句不等于上一句。更新池时保留尚未展示的 ID，加入新 ID，删除无效 ID。相同正文拒绝，避免不同 ID 造成视觉重复。
- 欢迎门禁位于认证与防窥门禁内，仅首页 / 与 /app 触发。每次文档加载及登录会话仅申请一次初始文案，StrictMode 共享同一个请求；完成后应用内导航不再次展示。打开设置等深链接直接到目的地。取句失败/超过 5 秒直接进入记录，可主动跳过等待。欢迎页本身启用现有防窥计时。
- 账号切换销毁欢迎页与设置局部状态，利用现有会话 scope 拒绝旧响应。文案不写 localStorage。
- 设置页支持添加、编辑、删除、开关和预览；修改立即保存，失败保留输入。409 保留草稿并要求重新载入配置，不能静默覆盖。从记录菜单转到设置编辑器，作为待编辑文本，保存后才入池。
- 备份导出新增可选 welcome 对象；导入仅在目标尚无配置时恢复，不覆盖现有池，旧备份仍可读取，轮换历史不导出。
- 视觉采用「日落明信片」：桃粉天空、杏色太阳、蓝紫和青蓝远山，半透明暖白文案卡与紫色进入按钮；装饰以 CSS 和 SVG 实现，不加载外部图片。系统无衬线承载控件，中文宋体用于文案。文案保留换行、不渲染 HTML，卡片下方为进入与换句按钮，无自动倒计时。手机使用单列布局，深色模式使用现有 dark class 切换为暮色色板，装饰不进入无障碍朗读。

### 未采纳方案及原因

- 仅 localStorage：不能跨端保存且容易账号混用。
- 每条请求完全随机：无法满足每次新一句与循环不重复。
- 云端 AI：本版无需外部服务或密钥，随机轮换足够验证体验。

## Risks / Trade-offs

- 每次首页启动新增一次请求 → 短等待、主动跳过、异常放行，不影响既有记录入口。
- 浏览器“重新打开”没有统一事件 → 文档重新加载/新标签页视为打开，焦点恢复与内部路由不算。
- 欢迎文案为私密账号数据但非 E2EE → 继承现有鉴权、no-store 与防窥，不声称管理员无法读取数据库。
- 数据库跨方言 → 采用已有类型约定，SQLite 实测；其他数据库未实测时明确记录。

## Migration Plan

新增 Alembic 0005，只建新表，不改历史数据。部署前备份，执行 uv run python -m cli migrate 后部署 Web；旧客户端不受影响。回退代码可保留新增表，不自动删除用户文案。
