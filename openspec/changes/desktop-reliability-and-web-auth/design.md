## Context

Electron 已有主进程提交幂等恢复，附件仍由 renderer 直接请求；JWT 轮换存储未加密。Web 为 React，后端为 Django。

## Goals / Non-Goals

完整实现 proposal 的桌面可靠性、浏览器授权、图标统一和 PyPI 迁移。保留现有密码登录以兼容旧服务器；不部署到用户生产环境。

## Decisions

### 方案选型

- 浏览器授权使用随机 loopback 端口、一次性授权码、S256 PKCE 和 state。后端仅接受 127.0.0.1 回调固定路径，码摘要及有效期落库，兑换条件更新确保单次消费。浏览器确认页面复用 Web 登录。
- refresh token 使用 Electron safeStorage 加密，迁移旧明文；不可用时只保持内存会话并明确提示。统一带超时的认证请求，401 最多刷新重放一次，网络故障保留凭证，状态通过 IPC 广播。
- 附件上传与预览在主进程执行。客户端暂存文件及元信息按服务器/用户隔离，上传状态逐项展示和重试；私密附件通过鉴权获取 blob，公开发布后服务端同步附件权限。文章响应补齐附件元数据，兼容仅 UID 的桌面历史文章。
- 草稿即时写入主进程并在关闭握手中 flush，保留销毁式窗口避免旧 DPI 问题。已有窗口重复打开仅聚焦。编辑框可固定置顶，按当前显示器定位。
- 图标采用仓库已有视觉资产中可辨识的气泡母版，生成多尺寸安装包和托盘资源，并显式配置窗口图标。

### 未采纳方案及原因

- 内嵌网页登录：无法复用系统浏览器登录态。
- 仅延长 token 有效期：无法修复断网、休眠和刷新状态问题。
- 全面放开 CSP/CORS：主进程传输更易控制目标来源和凭证边界。
- 把所有附件公开以支持 img：不符合私密内容预期。

## Risks / Trade-offs

- 新授权端点要求后端和 Web 同步发布 → 保留密码登录。
- 系统安全存储不可用 → 明确提示会话不持久化，禁止明文降级。
- S3 签名地址过期 → 根据附件 UID 重新获取鉴权预览。
- 关闭时 renderer 无响应 → 保留编辑窗口和主进程已收到的草稿，超时提示用户重试，避免未保存内容丢失。

## Migration Plan

更新 PyPI 锁文件、执行新增授权模型迁移，再发布 Web 和桌面；旧文字草稿兼容读取，旧 token 首次读取迁移。回滚应用不删除草稿或媒体。
