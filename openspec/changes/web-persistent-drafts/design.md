## Context

编辑器只有内存状态，附件 hook 包含 File 对象，已有 IndexedDB 依赖可存储结构化文件。认证在挂载编辑器前初始化。

## Goals / Non-Goals

目标：刷新和导航恢复完整草稿、明确失败、避免串账号或串编辑记录。非目标：自动发布、服务端草稿同步、PWA、真机验收。

## Decisions

### 方案选型

- IndexedDB 保存结构化草稿和未完成文件；key 包含规范化 API 地址、用户 id、新建或编辑 id。新资源 key 变化时重建编辑器状态。
- 加载完成前禁用输入，避免用初始空值覆盖磁盘草稿；输入后短延迟自动保存，导航卸载时提交最后快照。未落盘或写入失败时 beforeunload 提醒。
- 文件恢复后，未完成项变为可重试状态，不自动发送网络请求。发布成功和显式清除删除对应草稿，失败保留；保存队列与删除串行避免旧写入复活。
- 同一草稿采用版本检查，另一个标签页已修改时拒绝覆盖并提示保留当前内容。
- 接入时发现新建/编辑同时显示会共用全局编辑目标；提交回调显式绑定目标记录，确保新建草稿始终创建记录，避免覆盖正在编辑的记录。

### 未采纳方案及原因

- localStorage：不能直接存储 File，容量较小，无法满足附件恢复。
- 自动重发：可能重复创建，仍需独立幂等契约。
- 仅保留正文：会静默丢失附件和可见性。

## Risks / Trade-offs

浏览器存储被清理或配额不足时无法保证落盘，必须显示失败并提醒离开。并发冲突不自动合并，保留编辑器内容供用户复制核对。编辑草稿可能基于旧记录，恢复时显示原记录已更新的提示。
