# 操作请求预算修复设计

目标是完整修复 docs/request-count-audit.md 的已确认冗余，保持评论预览、正确筛选、远端更新和账号隔离。用户已要求全部修复；在现有工作区保留上一轮未提交修改，不提交或部署。

1. 后端所有 record_data 投影增加 comment_preview（按 create_time、id 升序最多 3 个 CommentOutput）和 comments_revision（评论集合版本）。批量查询预览，不能每记录追加 SQL。评论 GET 无 page 保留旧数组；提供 page 时返回分页 CommentPage {count,next,previous,results,revision}，默认每页 20、上限 100。公开与私有权限保持。
2. Web/移动 BBTalk 模型新增可选 commentPreview、commentsRevision，列表内联直接用预览，不逐卡片自动 GET。展开才分页加载；评论缓存限定当前账号/服务器，按 revision 失效，写入同步本地预览/计数并失效完整列表；旧服务端缺少新字段时兼容读取。跨挂载、取消编辑、删除撤销不重复取评论。远端刷新可更新预览与展开列表。
3. Web 统一初始/筛选触发，依赖具体标签名、关键词，不依赖整个 tags。焦点时间使用稳定 ref，合并 1 秒内事件；只按实际数据变化触发必要刷新。读取采用相同查询的在途复用，过期筛选请求可取消；不能因取消一个订阅者破坏另一个。
4. 附件 API 图片增加有界、短期、同会话内存缓存及在途复用。键包含服务器、账号/会话身份及 URL；禁止跨会话复用，权限变化与显式重试使缓存失效。不回退到跨账号 URL-only IndexedDB。
5. 移动端标签管理写入后只读取一次标签，复用结果同步 Redux。移动列表读取也合并重复、取消过期查询；普通逐文件上传、批量 N 条写入和必要 token/备份轮询保留。

验收以生产构建请求预算为主：冷首页 me+feed+tags=3；切换标签1，重复0；一次前台刷新最多2；取消编辑/立即撤销0；保存正文1–2、发布/删除1–2（必要筛选刷新最多另1）；相同图片并发1；100条带评论列表不产生100次评论GET；完整评论分页及缓存失效正确。测试覆盖身份切换、过期响应、评论写入/删除和服务端变动。
