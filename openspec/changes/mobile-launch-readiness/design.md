## Context

基于 Expo SDK 54，保留工作区已有长按录音与锁定录入改动。后端使用自定义 User/Identity，而非 Django AbstractUser。

## Goals / Non-Goals

实现可恢复的记录流程、明确公开边界、普通用户友好界面和可部署的账号找回。完整离线同步队列、社区治理系统、商业化和真实商店提交另行验收，不以代码完成替代上线验收。

## Decisions

### 方案选型
- 草稿使用现有按服务器/账号隔离的 AsyncStorage，增加顺序写入、短延迟保存及后台立即保存。提交和丢弃先等待写队列，防止删除后旧草稿复活。编辑草稿以记录 ID 隔离，保留原版本用于冲突检查。
- 原生待上传附件复制到应用文档目录，草稿存储元数据；上传失败保留重试入口。Web 预览对可持久化的数据采用本地表示并明确失败，避免假装 blob URL 可跨启动保存。
- 复用现有提交幂等机制，弱网先保住草稿并手动重试，不引入后台自动发布。
- 邮件恢复使用数据库保存随机令牌摘要、短期过期及单次消费。用户名与邮箱同时匹配，响应不泄露账号存在性，设置请求/确认限流。修改密码验证旧密码并使旧 JWT 失效；邮件功能默认关闭，配置后启用。
- 首页正文打开只读详情，菜单继续提供编辑；高级设置保留自建与存储能力；外观增加 system 选项。

### 未采纳方案及原因
- 不移除公开能力：用户仅授权优化，保留功能并加强风险说明；社区治理作为发布门槛记录。
- 不引入完整后台同步：跨设备冲突与附件队列需要独立范围，本次优先本地保存、恢复和可见重试。
- 不使用邮件里直接传新密码或长期令牌；不把未配置邮件服务显示为发送成功。

## Risks / Trade-offs

- 系统可能在异步保存前强杀进程 → 短延迟保存并明确保存状态，真机验证中断边界。
- 邮件送达依赖生产 SMTP → 本地邮件测试，不发送真实邮件；部署文档明确外部配置。
- SDK 与原生行为依赖 iOS 构建 → 类型检查、集成测试、Web 视觉验证之外保留 TestFlight 清单。

## Migration Plan

新增密码恢复模型并迁移；默认关闭邮件找回。现有草稿兼容读取，既有登录令牌允许在首次修改密码前继续工作。回滚前暂停密码恢复入口。
