## Context

上一轮只有组件和服务单元测试。本轮验证普通 Web 实际业务链路，先覆盖桌面 Chromium 与 375px 小屏 Chromium。

## Goals / Non-Goals

Goals：可本地/CI 重复运行的真实 API 浏览器验收，修复实际发现的问题。
Non-Goals：本轮不引入原生模拟器、不部署生产、不替代人工跨设备验收。

## Decisions

### 方案选型
- Playwright 管理 Vite 和测试专用 Django 进程，固定回环端口且不复用未知现有服务。
- Django 使用系统临时目录中的 SQLite、媒体、静态文件和密钥；环境变量覆盖本机数据路径，启动时迁移。
- 每个测试通过真实注册接口准备独立账号，随后使用 UI 登录和操作；断言刷新后状态验证真实持久性。
- 失败保留 trace/screenshot，CI 上传报告；测试不使用固定等待替代业务状态断言。

### 未采纳方案及原因
- API 全 mock：无法发现后端契约与持久性问题。
- 使用本机开发数据库：存在污染业务数据风险。
- 一次覆盖所有浏览器：先稳定关键路径，再扩展 WebKit/Firefox 和真机。

## Risks / Trade-offs

- 安装 Chromium 增加 CI 时间，使用依赖缓存并仅安装所需浏览器。
- 小屏仿真无法替代 iOS 键盘、手势和原生能力验收，明确记录边界。
