## Context

现有 FastAPI 路由保留 DRF 契约：尾斜杠、ORM 双下划线过滤、逗号分隔标签、400 字段字典。客户端遍布 Web、移动端、桌面端，附件历史 JSON 也保存旧 URL。数据库和业务权限必须保持。

## Goals / Non-Goals

目标：路由声明即接口契约，非法输入可定位，Swagger 可直接使用，客户端同步迁移。
不调整数据库、不重写认证、不删除历史数据、不引入框架抽象层。

## Decisions

### 方案选型

1. 保留领域前缀 `/api/v1/bbtalk` 和附件前缀；正式路由去除尾斜杠，存储 POST 集合、DELETE 详情。单独兼容模块注册隐藏的旧路径，保留完整响应和依赖元数据。HEAD 复用 GET 的完整契约。规范路径无需重定向。
2. `schemas/query.py` 声明分页、日期、排序、布尔参数；FastAPI 使用 `Annotated[Model, Query()]`。`tags` 用重复查询参数，日期使用 `created_from`、`created_to`、`created_date_from`、`created_date_to`、`created_on`。旧名在模型验证前转换；同时传新旧名拒绝歧义。
3. 记录 JSON `tags` 使用字符串数组，兼容 `post_tags`；标签排序、删除账号、PKCE、迁移请求都使用具名模型。保留导入文件内部 JSON 的扩展字段，不把业务存档当 HTTP 请求模型。
4. 保留原生 422；业务 APIError 不变。ID 使用现有短 UID 字符串，存储 ID 使用正整数，附件 ID 使用 UUID。Header 显式声明幂等键和 If-Match，PUT 与 PATCH 的必填字段分别声明。
5. HTTPBearer 和 Cookie 安全依赖替代路径猜测；可匿名附件接口声明可选鉴权。主要资源用 Pydantic 响应模型，防止凭据误返回；文件响应声明真实媒体类型。
6. 客户端直接使用正式 URL、新参数和标签数组，并解析 `detail` 数组为字段提示。错误详情不渲染为 `[object Object]`。
7. 记录、标签的规范 PUT 使用完整输入，PATCH 使用省略字段不变的输入；旧尾斜杠 PUT 保留原有局部更新语义。存储配置保持既有局部更新及空密钥保留规则。

### 未采纳方案及原因

- 一次性删除旧接口：会破坏已发布客户端与存量附件 URL。
- 继续手工解析并单独维护 OpenAPI：运行行为仍可能与文档漂移。
- 全面换为 `/api/v2/records` 等新资源名：不是 FastAPI 强制规范，超出本次必要改动。

## Risks / Trade-offs

- 422 变化影响依赖旧错误码的调用方 → 多端错误解析与升级文档同步；业务 409/401/403/429 不变。
- 日期边界影响搜索结果 → 保留服务器时区，无时区日期按配置解释，结束日期包含整日，测试跨 UTC 日界线。
- 自动注册别名丢失元数据 → 从完整 APIRoute 克隆，仅修改路径/文档可见性，测试 HEAD、鉴权、响应模型和多次应用工厂。
- 返回模型过严影响历史扩展附件 → 附件和上下文 JSON 保留开放结构，不缩窄已有业务数据。

## Migration Plan

后端与 Web 一起部署，原生端随版本升级；旧 URL 与旧参数保持兼容。非法输入改为 422。无数据库迁移，可回退代码。
