## Context

用户授权第一轮可靠性迭代，并明确移除 PWA。Web、原生移动端和桌面端继续各自维护。

## Goals / Non-Goals

Goals：移除 PWA 产品能力并让旧客户端安全退场；隔离账号数据；让更新入口和公共控件行为真实可用。
Non-Goals：本轮不实现自动下载安装、离线写入队列、AI、Widget 或上线部署。

## Decisions

### 方案选型
- 保留一个不拦截请求的 `sw.js` 退场脚本，接管旧 worker 后删除本应用历史缓存并自注销。新页面不注册 worker，只检查本应用相同 scope 的旧注册。清理不触及其他 scope、localStorage 或 IndexedDB。
- 缓存使用服务器地址和用户 ID 组成的 scope，SQLite 使用复合主键并保存列表顺序；不读取旧版无归属缓存。
- 使用独立会话模块提供 scope、代次和切换通知，避免 auth/store/cache 循环依赖。Redux 在切换时重置，并屏蔽旧代次异步请求结果。
- 桌面通过已有 IPC 打开固定 GitHub Releases 页面，移除伪造检查状态。
- Modal 增加焦点限制、恢复、标题关系和内容滚动；Select 使用浏览器原生选择框获得键盘支持。

### 未采纳方案及原因
- 仅删除 PWA 插件：旧 worker 可能继续提供旧页面。
- 退出时只清列表：磁盘缓存和在途请求仍能恢复旧数据。
- 本轮接入自动更新器：需要安装包签名、发布源和实际升级验收；先提供真实发布入口。

## Risks / Trade-offs

- 旧客户端再次联网访问才会完成退场；不强制刷新正在写作的页面。
- 历史无归属离线缓存被丢弃，登录后从服务器重新获取；服务器数据不受影响。
- 本轮测试验证逻辑与浏览器交互，原生设备和安装包升级需独立验收。

## Migration Plan

常规构建部署；保留退场 worker URL 和 no-cache 响应以覆盖长期未访问的旧安装。回滚产品代码时也应保留缓存隔离修复。
