## Context

本轮修复已审计的五个移动端缺口，保留 FastAPI 3.0 规范接口和现有页面结构。

## Goals / Non-Goals

目标：草稿附件不公开，文件请求可恢复且隔离会话，导入反馈真实完整，定位编辑可保存，列表音频不自动下载。无后端接口扩展、依赖升级或数据库变更。

## Decisions

### 方案选型

- 新增 `fileRequest.ts`，提供捕获会话的请求上下文，以及泛型响应读取函数。上传 60 秒、导入导出 120 秒，期限包含响应体读取；只对明确 401 刷新并重试一次，网络错误不重放写请求。刷新本身 10 秒超时；令牌拒绝触发现有退出逻辑。会话改变取消请求，并禁止迟到结果触发保存、分享或提示。
- 上传显式 `is_public=false`，后端沿用发布/编辑时的附件权限同步；不修改历史附件状态。
- 导入显示全部统计、partial 和错误明细，非 2xx 使用现有安全错误解析。页面选择文件及导出分享阶段同样检查会话。
- PATCH 仅在调用方提供 context 时发送，空对象允许清除位置。
- 原生音频卡片仅检查本地缓存，点击后下载并播放；拒绝非 2xx，失败可重试。卸载/换源后忽略迟到下载。独立播放页补齐私有媒体鉴权。文档明确 Range 已支持，下载缓存是客户端策略。
- 音频缓存使用 v2 账号/来源键，不信任旧 UID 缓存；每次下载写独立 `.part`，完整成功后移动至正式缓存。失败或迟到下载仅清理自身暂存文件。异步 ZIP 写入跨越会话切换时清理该操作的导出文件。

### 未采纳方案及原因

- 不在每个页面复制刷新逻辑，避免错误和会话策略分叉。
- 不自动重试断网或 5xx 的导入/上传，避免服务端已完成后重复写入。
- 不直接切换全量流式播放：保留已有 Expo 原生缓存路径，更容易验证兼容性；按需加载已解决列表流量问题。

## Risks / Trade-offs

- 历史公开草稿仍保持原状态：说明升级不会追溯修正，避免误改合法公开附件。
- HTTP 请求取消不能撤回服务器已完成的导入：超时提示先核对，保留重试选择。
- 原生音频及系统分享需设备补充验收；自动化验证请求、会话、缓存及组件状态，不冒充真机结果。

## Migration Plan

随 API 3.0 发布客户端，旧协议令牌需重新登录；保留草稿及待提交标识。不新增配置。
