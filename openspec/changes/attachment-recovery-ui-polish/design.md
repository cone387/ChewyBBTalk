## Context

现有 Web 使用 Promise.all 上传，失败会丢弃整个批次的界面结果。页面捕获发布异常却未向编辑器抛出，导致错误清空。保留现有视觉风格和阅读/编辑入口。

## Goals / Non-Goals

目标：逐文件恢复、明确错误、长内容和触屏可操作。非目标：新阅读入口、PWA、跨刷新附件草稿、原生语音改造或全站主题重构。

## Decisions

### 方案选型
- 独立 hook 保存文件及状态；手动重试仅处理失败项，移除/卸载中止请求并拒绝迟到结果。
- 上传存在未完成项时阻止发布，避免静默漏附件；失败项可以移除。
- 页面向编辑器传播发布异常，编辑器就地显示错误并保留字段；请求期间锁定表单，避免成功后清掉后来输入。
- 真实临时后端验证成功持久化，Playwright 定向注入上传及发布失败；截图覆盖小屏、横屏、大字体和深色偏好。沿用项目原有字体、色彩和布局。

### 未采纳方案及原因
- 自动整批重传：会重复上传成功附件。
- 自动重试发布：服务器已接收但响应丢失时可能重复创建，需后续幂等契约。
- 全站新增深色主题：本轮先检查现有主题支持并记录边界，避免扩展到产品重设计。

## Risks / Trade-offs

- File 保存在内存，刷新或离开页面会丢失待重试项；文档明确边界。
- 中止客户端请求不保证服务端回滚，已有未关联附件治理不在本轮扩大。
- 浏览器模拟不等于原生真机；键盘、语音、后台恢复不能据此标为通过。
