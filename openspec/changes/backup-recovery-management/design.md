## Context

当前 DATA_DIR/backups/<用户 id>/ 中已有命令生成的 ZIP。导出附件异常被跳过；导入已能重写附件引用并恢复评论，但结果 UI 缺少附件/评论统计，部分失败仍显示成功。

## Goals / Non-Goals

目标：账号内可见的备份管理、可信的完整备份、恢复演练与失败反馈。非目标：跨账号恢复权限、云端定时任务平台、在线数据库时间点恢复、真机验收。

## Decisions

- 延用文件目录和原子替换，不为已有 ZIP 增加必需的数据库迁移。共享服务提供创建、列表、读取与保留清理；每用户状态 JSON 记录开始/完成/失败。历史 ZIP 标为历史备份，不虚称已验证完整。
- 使用操作系统文件锁串行同账号创建，锁随进程结束释放。若状态仍为运行中但锁已释放，展示中断状态；不会因时间猜测而删除活跃锁。Windows 使用 msvcrt，Linux 使用 flock。
- 创建接口同步完成，前端显示处理中；请求中断时通过列表重新核对真实状态，避免重复创建。暂不引入无持久队列的后台线程或 Redis/Celery；慢备份仍可用已有宿主机命令。
- 路径只由认证用户 id 和已校验文件名构造，拒绝路径穿越和符号链接越界；下载使用认证请求，不把本地路径或凭据放进响应。
- 完整 ZIP 增加完整性清单，记录附件成员、大小和摘要。任何必需附件读取失败则整份备份失败，已有备份不受影响。旧版 ZIP/纯 JSON 保持可导入，缺件与部分失败明确显示。
- 从真实本地存储导出到另一隔离账号并恢复，核对正文、标签、评论、可见性、上下文、置顶、时间和附件字节及引用。发现缺字段时修复；不以仅 mock 存储成功作为完整恢复证据。

## Risks / Trade-offs

- 大附件导致同步创建耗时 → UI 区分请求失败和已确认备份失败，列表可刷新核对；保留 CLI。
- ZIP 备份与服务数据同盘 → 页面说明下载异地保存；本功能不承诺抵御宿主机磁盘损坏。
- 导入数据库事务无法回滚外部文件 → 先校验完整性再写入，失败文件跟踪清理，统计结果不得误报。

## Migration Plan

延用默认目录，增加 BACKUP_ROOT 配置供 API 与命令共用；显式 --output-dir 仍可覆盖命令路径。先运行自动测试与恢复演练，再提交推送。已有 ZIP 不修改内容。
